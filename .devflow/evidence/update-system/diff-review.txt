REFUTATION ADJUDICATION (requested)
The security-auditor's F1 exploit example is technically FALSE as stated: the string
https://github.com@evil.example/path does NOT start with "https://github.com/" (the @
occupies the position where the prefix demands the slash), and any string that does start
with that prefix necessarily parses with host github.com (the authority ends at the first
slash, leaving no room for userinfo). The lead's refutation is confirmed. Caveats: a
slash-less prefix check would have been bypassable by that exact URL, and the new
index.js:499-500 comment still cites the example as if it defeated the actual old check
(N1). The applied origin hardening is nonetheless sound defense-in-depth (normalizes
case/port, rejects nothing legitimate) and is pinned by regression tests. Verdict: the
hardening is kept on merit; it was not an exploitable-bug fix.
