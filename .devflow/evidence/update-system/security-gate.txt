Scope: git diff of index.js, client.js, package.json, SECURITY.md, docs/api.md,

Trust model (declared): host dsh authenticates the local /api routes; the browser client
is a bundle in the dsh webview origin; GitHub (releases API) and npm registry are the
trusted update sources over TLS; the repo owner is the supply-chain root for releases.
No alternative assumption was needed: every traced path stays inside these boundaries.

Traced and clean (no credible attack path):
1. XSS: release notes are rendered only as React text children (client.js:783, 753).
   Zero occurrences of dangerouslySetInnerHTML / innerHTML= / document.write / eval /
   new Function in client.js and index.js. plainNotes (client.js:585) is cosmetic
   stripping; the security property is text-child rendering, which escapes by design.
2. href flows: row link uses server-gated info.url (client.js:754); dialog record url is
   prefix-checked (client.js:715); show() builds the tag URL from a constant prefix plus
   a version that must fully match the anchored x.y.z regex (client.js:568, 573, 674, 695).
   All anchors carry rel="noopener noreferrer" (client.js:754, 780, 787).
3. Install spec injection: impossible. index.js parseVersion is anchored
   ^v?(\d{1,6})\.(\d{1,6})\.(\d{1,6})$ (index.js:487); the route throws unless the tag
   parses (index.js:547-550) and latest is the tag minus one leading v, so the spec
   "dsh-orchestrator-kit@<latest>" (client.js:630) and the tarball fallback
   (client.js:633) can only contain digits and dots — no spaces, flags or registry args.
   npm URL on the server is likewise bounded (index.js:558).
4. ?current=1: no path traversal — file paths are fixed via import.meta.url
   (index.js:27-31, 528); the query param is only compared === '1' (index.js:819).
5. Error leakage: the route logs via redactText + safeErrorText (index.js:832; helpers at
   index.js:169-180) and the 502 echoes only String(error.message) of errors generated by
   this credential-free flow; no secrets are sent outbound, so none can be reflected.
6. localStorage: all reads/writes in try/catch (client.js:592, 638, 642, 700-701, 721-723);
   WHATS_NEW_KEY JSON.parse is shape-guarded (client.js:707-715: versionOf on version,
   string check on notes, prefix check on url); language keys filtered by an anchored
   BCP-47 regex on both server (index.js:511-520) and client (client.js:576-577), which
   blocks __proto__/constructor-style keys; stored values are never interpolated as code.
7. inject/dispose: manager binding is cleared on dispose (client.js:2103-2106 inner scope
   effect + fiber.dispose at client.js:2080-2084). The inject grants only what the host
   module provides; the client reads only remote.pluginManager.
8. GET route: read-only, no server mutation; disclosure limited to the installed version —
   negligible sensitivity on an authenticated local route.
9. Test hygiene: scripts/test.mjs diff only renumbers contracts (6 to 7 routes, 77 to 78
   pack entries, byte ceiling re-measured); the forbidden-token scan and hygiene walker
   are untouched.

Findings (defense-in-depth; no exploitable trace found for either):
F1. LOW — prefix check bypass on release URL. index.js:569 and client.js:715 accept any
    string starting with "https://github.com/", including userinfo tricks such as
    "https://github.com@evil.example/path" whose real host is not github.com. Prerequisite:
    control of the GitHub release payload — the repo owner or GitHub itself — who is
    already the supply-chain root and could publish a malicious npm version anyway, so no
    new capability is gained. Impact if it ever fired: a non-github href in the update row
    or dialog footer. Smallest fix: parse with new URL(value) and require
    origin === 'https://github.com' (server side suffices; client.js:715 stores a value
    that already passed the server gate). Verify: unit test rejecting
    "https://github.com@evil.example/x".
F2. LOW — client trusts the host-route shape for the install spec. client.js:630/633 build
    name@latest and the tarball URL from the response without re-checking versionOf(info.latest)
    or the package name. No credible path inside the declared model (requires compromising
    the authenticated host or the webview origin, both out of scope). Smallest fix: in
    install(), bail out unless versionOf(info.latest) !== undefined and info.name is the
    expected npm name. Verify: VM test feeding a malformed latest and asserting the install
    call never happens.
