## [Unreleased]

### Added

- Per-role fallback route for quota-resilient dispatch: role cards gain an optional `fallback: { provider, model }` frontmatter pair — the one-shot retry route the Lead applies when a role dispatch or its child dies from a model-availability failure (quota exhaustion, concurrency or rate limits, provider outage). When the card declares no fallback, the retry runs without a route so the child inherits the session default; a second model-availability failure ends retries and is reported. The panel edits the pair per role (provider + model selects with a "None — session default" reset), the route save validates it fail-closed against the live catalog (409/503 like any route), reset-route saves leave it untouched, the roles summary exposes `fallbackProvider`/`fallbackModel`, the audit trail records it in previous/next summaries, routing profiles export/import it, diagnostics flag fallback pairs outside the live catalog, and the Orchestrator persona + dev-flow skill prescribe the one-fallback-attempt retry discipline (declared degradation on a second failure). Task-level failures, user aborts and refusals are not route failures.
- `Server-Timing` header on successful responses when a timing metric was measured — roles reads, catalog reads, route validation and writes (durations only); an unchanged save with no route validation carries no header. A panel legend line shows the last load timings.
- Invalid-card surfacing: the roles listing reports parse-failed cards in an `invalid` list with redacted errors, and the panel shows a warning banner naming the cards that cannot be edited until their frontmatter is fixed.
- Unchanged-save indicator: a save identical to the card's current settings answers `unchanged: true` without acquiring a lock or writing, and the panel shows an "Already up to date" notice.
- Panel i18n in English, Português (BR) and 简体中文: a header select switches the panel between Auto (host language), English, Português (BR) and 简体中文, defaulting to the harness language. The override is panel-scoped and remembered for the browser session (best-effort `localStorage`; it may not survive a Desktop app restart). While the plugin is active, `pt-BR` becomes a selectable harness language (removed on deactivation), and generic `pt` resolves to the pt-BR dictionary.
- Locale parity and sync tests: the three `locale/*.json` files must carry identical panel key sets against a frozen 72-key schema, and the dictionaries embedded in `client.js` must deep-equal the JSON `panel` sections.
- Structural t-usage gate: a sentinel-bind render matrix proves every panel string flows through the locale system and all 72 dictionary keys are exercised.
- `npm pack` guard: the dry-run file list must match a frozen 69-entry contract, and every file extracted from a real tarball is scanned for forbidden tokens.
- View controls on the settings panel: a search box (role name or description), a status filter (All statuses / Routed / Inherits chat / Disabled), a sort select (by name, routed first, inherits first — applied within each section) and a density select (cards or compact one-line rows). All compose AND-style with the phase tabs, and a filtered-out view shows a distinct no-match state. Each tab shows its routed / inherit / disabled breakdown in saved state.
- Unsaved-changes protection: editing a card marks it unsaved (amber border and an " (unsaved)" name suffix), leaving the page with dirty drafts triggers the browser's leave confirmation, Ctrl+S / Cmd+S saves the focused card, and unsaved drafts survive section remounts via mtime-keyed hoisting — kept only while the card's server mtime still matches the stored base, discarded when an external edit changed the card. The plain Refresh button still resets drafts.
- Undo last save: every successful save offers a per-card Undo that restores the pre-save settings; one level per card, session-only, never persisted. The undo request carries the recorded post-save `mtimeMs`, so a card changed on disk in between answers `409` with the conflict message.
- Corrective actions on save errors: a `409` conflict message gains a "Reload saved state, keep edits" action that re-reads the saved state and reapplies the draft without ever resending the stale `mtimeMs`; a `409` on a save that set a reasoning effort adds a hint pointing at the effort select. The 503 lock-timeout response keeps its server-provided guidance.
- Accessible save feedback: a shared polite live region announces the last save or undo outcome, the header counts act as a polite live region, and a saved card keeps a green border until the next change (cleared by interaction, not timers).
- Effective-route hint on inherit cards (shows the chat-default provider / model when the harness catalog exposes one) and `content-visibility` space reservation on comfortable grid cards.
- Same-session panel prefs: tab choice, legend state and density persist through best-effort `localStorage` with the same semantics as the language override; search and sort are transient.
- Per-phase batch apply: on a phase tab, each section header carries an "Apply to phase" button that copies the source card's draft route/effort to every other card in the section as its own validated save (per-card expected `mtimeMs`). Per-card results: `409` conflicts continue and are reported, a non-409 failure stops the run, and a Cancel button stops after the in-flight card — never atomic.
- Routing profiles: "Export profile" writes the saved routes of all roles to a versioned JSON (`version: 1`, generator, roles keyed by id, no mtimes); "Import profile" validates every entry before writing anything (unsupported version, half-written routes or malformed ids reject the whole file), skips ids unknown locally, refreshes the card list for fresh mtimes, then applies each entry as a normal save.
- Append-only change log: every successful save appends one JSONL record (time, role id, previous/next route, origin — no secrets, no absolute paths) to `.orchestrator-audit.jsonl` beside the cards, written inside the existing write lock. Best-effort: an audit-write failure never fails or rolls back the save. A new `GET /api/dsh-orchestrator-kit.events` route returns the last 50 records (malformed lines counted as skipped, empty list when the file does not exist), and the panel's Recent changes section shows them on demand.
- Installed-card diagnostics: a new read-only `GET /api/dsh-orchestrator-kit.diagnostics` route reports roles missing versus the `craft/` sources, cards with invalid frontmatter, routes outside the live catalog, and cards whose body differs from the craft source. Computed on demand, never cached, and it degrades gracefully when `craft/` is absent (`craftAvailable: false`, still `200`); the outside-catalog list requires a live catalog and is omitted when it is unavailable. The panel shows the report in a legend section.
- Craft install script: `node scripts/install-craft.js [--dry-run]` copies the 20 role cards into the agents root and the dev-flow skill tree into `<agents home>/skills/dev-flow/`. It always skips existing files (no overwrite mode, no backups), verifies path containment, prints relative paths only, and turns a held writer lock into actionable retry/operator guidance with exit code 1.
- Read-only mode: `DSH_ORCHESTRATOR_READONLY=1` (or `true`) makes the server answer every save with `403` (`code: 'readonly'`) before reading the body or touching disk, and the roles bootstrap carries the flag; the panel disables every mutating control and shows a read-only notice, keeping export available.
- Native V8 coverage gate: `NODE_V8_COVERAGE` JSON is aggregated by an own-source parser (URL-to-filesystem containment, `node_modules` excluded) and enforced at 70% statements / 60% functions. Coverage data and report output go to separate external directories; the gate is runnable locally with the two commands in [CONTRIBUTING.md](CONTRIBUTING.md) and is mirrored in CI and the publish workflow.
- Support banner in the settings panel: under the header, a dedicated banner asks for a GitHub star ("Enjoying Orchestrator Kit? — a star helps other people discover the plugin") with a gold call-to-action that opens the repository. The star twinkles with a soft glow, two sparkles drift around it, the button lifts on hover and pops when clicked, and the animations ship as a `<style>` element inside the panel. Answering is remembered in the panel prefs: starring thanks the user for a few seconds and the banner never returns; the dismiss button hides it for good.
- `client.js` byte budget: an in-suite assertion enforces the versioned 135168-byte (132 KiB) ceiling against the measured 133773 bytes (1395 bytes of headroom). Raising the ceiling requires an explicit commit with a measured rationale; the assertion never self-adjusts. The 100 KiB → 128 KiB bumps cover the support banner and the update system additions, and the 128 KiB → 132 KiB bump covers the fallback-route UI and its three-language panel strings while keeping the panel bundle small. Until that explicit commit, `client.js` is byte-frozen at 133773 bytes — even an in-budget edit must update the recorded measurement in the same commit.
- Six durable reference documents in `docs/`: `api.md` (the seven routes), `architecture.md`, `glossary.md`, `recipes.md`, `role-card.md` and `troubleshooting.md` — all shipped in the npm tarball.
- Documentation guards: `scripts/docs-parity.mjs` checks that the three READMEs share headings, table rows and fenced blocks, and an in-runner checker resolves every relative Markdown link and heading anchor without network access.
- Promotional motion-graphics demo (`assets/demo.gif` and `assets/demo.mp4`) featured in the three READMEs.
- Update system: about 15 seconds after every startup the panel checks GitHub releases for a newer version through a seventh route, `GET /api/dsh-orchestrator-kit.update` — read-only outbound GETs (GitHub releases API, npm registry as the installability double gate `newer: npm.ok`), no credentials, 10-second timeout, `502 { ok: false, error }` when the GitHub probe fails, and a zero-network `?current=1` mode serving the shipped per-language notes. Nothing installs automatically: an Updates row between the support banner and the message banners offers one button that installs through the harness plugin manager (with an exact-tarball fallback when the manager answers `already-installed`), covering the current, available, manual (non-npm copies are manual-update-only), restart-required, installing and error states, and it shows an `installed` version when the disk is newer than the running code. A What's-new dialog (shell overlay) shows the installed version's release notes per language with English fallback, once per version, fed by the shipped `release-notes.json`; its star line reuses the support-banner prefs state. The manifest injects `@deepseek-ai/dsh-api-remotes` so the panel can reach the plugin manager.

### Changed

- Redesigned the settings panel: responsive card grid, a segmented phase filter (All roles / three Craft phases / Other) with keyboard-navigable tabs, a collapsible legend explaining every setting, per-role status badges (Routed / Inherits chat / Disabled), header summary counts, and per-field help text. Contrast and narrow-layout overflow fixed; theme tokens used throughout.
- Strict frontmatter write gate: anchors, aliases and custom YAML tags are refused on writes, with a 65536-byte frontmatter cap and a nesting limit. Anchored, tagged or deeply nested cards stay listed but read-only (writes return 400) until cleaned; aliased or oversized cards fail the listing parse and appear only in the invalid-card warning banner.
- Route-save request limits: bodies above 65536 bytes are rejected with 413 before any disk read, and only known fields are accepted (unknown fields return 400).
- Role-card listing now uses bounded parallel reads (8 workers); the sorted response order is unchanged.
- A held writer lock now returns an actionable 503 error (`code: 'lock-timeout'`) naming the relative lock file with retry and operator guidance, instead of a generic 500; lock files are never removed automatically.
- Panel strings (labels, badges, notices, banners, legend, empty states) resolve through the locale system and re-translate live on language switch; role, catalog and effort names and counts remain untranslated data. Phase tabs and sections are keyed by stable ids (`discovery` / `planning` / `verification` / `other`); rendered English text is unchanged.
- The English-only test policy is replaced by trilingual parity: locale key parity, registered-dictionary sync and the structural t-usage gate (user decision).
- Remounting the settings panel skips the catalog refetch while a cached catalog exists (roles always refetch; an explicit refresh always refetches both).
- The panel now disables every mutating control when the server is in read-only mode (`DSH_ORCHESTRATOR_READONLY`), mirroring the flag from the roles bootstrap; the server `403` remains the authoritative gate.
- The panel now talks to six routes: the four original ones plus the new `GET /api/dsh-orchestrator-kit.events` and `GET /api/dsh-orchestrator-kit.diagnostics` read-only routes.
- CI and publish workflows gained a mirrored `Coverage gate` step: the emit run writes V8 data to an external directory under `runner.temp` and the report run writes to a separate one, reading the data through `--coverage-dir` (both outside the checkout).

### Security

- Secrets and user-home paths are redacted to `[redacted]` and `[home]` markers in server logs and HTTP error bodies; error codes and context are preserved. Data fields in successful responses are never redacted; error text inside a success envelope (`invalid[].error`) is redacted like any error.
- The change log stores role ids and route values only — never secrets, never absolute paths, never card contents — and both new routes redact error text like every other error path. The readonly gate answers `403` before reading the request body or touching the filesystem, so a read-only server performs no work for save attempts. The install script verifies path containment before any write, prints only agent-root-relative paths, and never creates backups.

## [0.1.0] - 2026-11-18

### Added

- Settings control panel **Settings → Orchestrator**: the 20 pipeline roles grouped in the three Craft phases, with per-role Disabled toggle, Provider, Model, lazily loaded Reasoning effort and Save.
- Fail-closed validated HTTP routes: `GET /api/dsh-orchestrator-kit.roles`, `.catalog` and `.efforts`, plus `POST /api/dsh-orchestrator-kit.route` — unknown role, model or effort returns 409; unavailable catalog returns 503.
- Atomic locked writes of role-card frontmatter: file lock, TOCTOU guard, post-write revalidation and expected-`mtimeMs` concurrency check.
- Orchestrator preset persona with the 20-role dev-flow pipeline included.
- Craft bundle: 20 role cards, the dev-flow skill and 9 playbooks, copyable to `~/.agents/agents` and `~/.agents/skills/dev-flow`.
- CI workflow and trusted-publishing release workflow.
- Animated showcase (`docs/showcase.svg`).
